# Workbench P1.1 + P1.2 Implementation Plan (persistent checkpoints, `/diff`, diff panel)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewind checkpoints survive restarts, every finished turn reports what files changed, and both frontends can show, diff and revert those changes.

**Architecture:** `FileState` keeps its per-turn before-image stack but mirrors it to disk through a new `CheckpointStore`. A pure `changes.ts` turns before-images plus the files on disk into summaries and unified diffs. Each turn emits a small `changes` event (summaries only); full diffs are fetched on demand over IPC. The CLI gets `/diff`; the desktop gets a `DiffPanel`.

**Tech Stack:** TypeScript, Node 22 fs, Vitest, React + Testing Library, `diff` (jsdiff) for patches.

**Spec:** `docs/superpowers/specs/2026-11-21-workbench-design.md` (goals 1 and 2; P1.3 line comments, P1.4 usage, P1.5 files, P1.6 terminal get their own plans later). Deviation from the spec text, my call: the 200 MB checkpoint cap is **per chat**, not per workspace, because chats are stored independently; update the spec when merging.

## Global Constraints
- `src/core` stays free of Electron/React imports. English-only UI, CLI output, errors and docs.
- New IPC channels: add to `IpcContract` and `INVOKE` (`src/shared/types.ts`), a validator in `src/main/validate.ts`, a handler in `src/main/ipc.ts`.
- Fail closed: the renderer sends a path only as a key; main checks it is one of the turn's changed paths and never touches any other file.
- Tests never touch the network and use a throwaway `HOME` (`src/core/test-home.ts`).
- Before each push: `npm run lint && npm run typecheck && npm test && npm run build`. Known container-only failure: `bash.test.ts` process-group timeout.
- Work on a feature branch and PR to `main`; do not tag or release.

## Review Focus
1. Binary file or file containing NUL: summary shows `binary`, no hunks, revert still works.
2. Very large file (> 2 MB) or diff over 200,000 chars: summary shows sizes, diff text is truncated with a visible marker; never hangs the UI.
3. File the agent created then deleted in the same turn (net no change): not listed as a change.
4. Corrupt or half-written checkpoint manifest after a crash: that turn is skipped with one warning, the rest load.
5. User edited a file after the turn and then clicks revert: the before-image is still restored (the UI asks for confirmation first); a path not in the turn's change set is refused.

### Task 1: CheckpointStore

**Files:** Create `src/core/checkpoints.ts`; Test `src/core/checkpoints.test.ts`.

**Interfaces:**
- Produces:
  ```ts
  export interface TurnRecord { id: number; files: Map<string, Buffer | null> } // abs path -> original bytes, null = did not exist
  export class CheckpointStore {
    constructor(dir: string, o?: { maxBytes?: number }) // default 200 * 1024 * 1024
    load(): Promise<{ turns: TurnRecord[]; warnings: string[] }> // oldest first, corrupt turns skipped
    save(turn: TurnRecord): Promise<number[]> // returns ids evicted to stay under maxBytes (oldest first, never the turn just saved)
    remove(id: number): Promise<void>
  }
  ```
- Layout: `<dir>/blobs/<sha1>` (content-addressed, shared across turns) and `<dir>/turn-<id>.json` (`{ id, files: { [path]: sha1 | null } }`), manifest written via temp file + rename.

- [ ] **Step 1: Failing tests** (`checkpoints.test.ts`, temp dir): `round-trips a turn including a null (new file) entry`; `identical content across turns is stored once` (blobs dir has 1 entry); `evicts the oldest turns when over maxBytes and returns their ids, keeping the newest` (maxBytes 10, three 6-byte turns → returns `[1,2]`... assert newest survives); `a truncated manifest is skipped with one warning and the others load`; `remove deletes the manifest and garbage-collects blobs no turn references`.
- [ ] **Step 2:** Run `npx vitest run src/core/checkpoints.test.ts`; expect FAIL (module missing).
- [ ] **Step 3:** Implement the class per the layout above; size = sum of referenced blob sizes across kept turns.
- [ ] **Step 4:** Run the same command; expect PASS.

### Task 2: FileState persistence, before-image queries, per-file revert, and wiring

**Files:** Modify `src/core/filestate.ts`, `src/core/agent.ts` (constructor, `load`, `clear`, rewind), `src/core/session.ts` (add `Transcript.checkpointDir: string` = `<sessionDir>/<id>.checkpoints`); Test `src/core/filestate.test.ts` (extend) and `src/core/agent.test.ts` (extend).

**Interfaces:**
- Consumes: Task 1 `CheckpointStore`, `TurnRecord`.
- Produces on `FileState`:
  ```ts
  attach(store: CheckpointStore): Promise<string[]>        // loads turns into the stack; returns warnings; fork() shares the store
  beforeImages(scope: 'turn' | 'all'): Map<string, Buffer | null> // 'turn' = newest entry; 'all' = per path the OLDEST before-image across the stack
  revertFile(path: string, scope: 'turn' | 'all'): Promise<boolean> // false if path not in beforeImages(scope); restores bytes (or deletes if null); removes the path from every entry it was reverted through and persists
  ```
  `record()` additionally persists the newest entry (`await store.save`) and drops evicted ids from the bottom of the stack; saves are serialized through one promise chain so parallel tool calls cannot interleave. `rewind()` calls `store.remove(id)` after the pop.
- `AgentSession.load(messages, store)` and `clear()` create a fresh `FileState` and `attach(new CheckpointStore(store.checkpointDir))` when a transcript is set. After a resume, turns restored from disk have no history start; `AgentSession.rewind()` already pops `starts` as undefined and then restores files only. Say so in the rewind notice: `"Restored files from an earlier run; the conversation is unchanged."`.

- [ ] **Step 1: Failing tests:** `a new FileState attached to the same dir sees the previous turns and rewinds them` (record, discard object, attach new one, `rewind()` restores bytes); `beforeImages('all') returns the oldest before-image per path`; `revertFile('turn') restores only that path and leaves others`; `revertFile refuses a path that was not changed (returns false, file untouched)`; `a file created and deleted in one turn reverts to absent`; in `agent.test.ts`: `resumed turns rewind files only and say so`.
- [ ] **Step 2:** Run `npx vitest run src/core/filestate.test.ts src/core/agent.test.ts`; expect FAIL.
- [ ] **Step 3:** Implement per Interfaces. Stack entries become `{ id: number; files: Map }` with ids from a monotonically increasing counter seeded from the highest loaded id.

### Task 3: Change computation

**Interfaces:**
- Consumes: `FileState.beforeImages`.
- Produces:
  ```ts
  export interface ChangeSummary { path: string /* workspace-relative, forward slashes */; status: 'added' | 'modified' | 'deleted'; additions: number; deletions: number; binary: boolean; tooLarge: boolean }
  export function summarizeChanges(images: Map<string, Buffer | null>, root: string): Promise<ChangeSummary[]> // sorted by path; entries identical to current content are omitted
  export function diffFor(images: Map<string, Buffer | null>, root: string, path: string): Promise<string | undefined> // unified diff; undefined if path not in images; binary/tooLarge return a one-line note
  ```
